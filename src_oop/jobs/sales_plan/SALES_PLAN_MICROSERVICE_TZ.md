# ТЗ: поля плана продаж для нового сервиса

Основа ТЗ — актуальные колонки вкладки [«План продаж v2.0»](https://docs.google.com/spreadsheets/d/1_ZFKBxelzM3tJB9TTwab1watklasAtSoWSHhUsAZC7E/edit) по состоянию на 23.11.2026. Новый сервис **только рассчитывает данные для собственного интерфейса**; записывать результат обратно в Google Sheets не требуется.

Расчёт ведётся по одному `wild` за выбранный месяц и дату отчёта. **Главный план — «План заказов, руб v2.0»**. В формулах ниже «факт» означает только заказы с положительной суммой с первого числа месяца по дату отчёта включительно. Проценты показываются как доли: `0,84` = `84%`.

## Поля в порядке колонок Google Sheets

| Колонка | Поле в таблице | Откуда брать или как рассчитывать в новом сервисе |
| --- | --- | --- |
| A | **Месяц** | Месяц выбранной даты отчёта, формат `ММ-ГГГГ`. |
| B | **Менеджер** | `sales_plan_category_manager_reference`: менеджер предмета, действующий на дату отчёта. **Для итогов по менеджерам факт распределять отдельно по дням заказов:** каждый день относится менеджеру, который вёл товар именно в этот день. |
| C | **WILD** | `sales_plan_accounting_category_reference.wild`. Один товар — одна строка, без повторения по артикулам или категориям. |
| D | **Предмет** | `sales_plan_accounting_category_reference.subject_name`: единственная учётная категория `wild`. |
| E | **Дней с остатком** | Число дней от начала месяца по дату отчёта включительно, когда в `sales_wild_status_daily` у товара `is_active = true`. Отсутствующий дневной статус не считать активным. |
| F | **Количество план** | Месячная доля квартального плана в штуках из `sales_plan_accounting_category_reference`, округлённая до целого. В октябре–декабре 2026 использовать `quarter_4_units_2026`. |
| G | **Количество факт** | Сумма `funnel_daily.order_count` по положительным заказам. Связать `funnel_daily.nm_id` с `article.nm_id`, затем взять `article.local_vendor_code` как `wild`. |
| H | **Цена плановая** | `sales_plan_accounting_category_reference.plan_price`. Для уже зафиксированного плана v2.0 использовать цену, сохранённую вместе с месячным снимком, даже если актуальная цена позже изменилась. |
| I | **Цена фактическая** | `Факт заказов, руб / Количество факт`, округлить до целого рубля. Если заказов нет — пусто. |
| J | **План заказов по годовому, руб** | `Количество план × Цена плановая`. Сравнительный план; не использовать для основного процента выполнения. |
| K | **План заказов, руб v2.0** | **Основной месячный план.** Если остаток на начало месяца неизвестен — не рассчитан. Если остаток `< 50` шт. — `0`. Иначе `min(Количество план, Остаток на начало месяца) × зафиксированная плановая цена`. Для ноября 2026 взять готовое `sales_plan_monthly_v2.plan_orders_rub_v2`; для следующих месяцев рассчитывать из сохранённого месячного снимка. |
| L | **Остаток на начало месяца** | Для ноября 2026 — `sales_plan_monthly_v2.available_quantity` (свободный остаток из архивного UNIT на 01.11). Для следующих месяцев — сохранённое значение поля **«Остаток»** из [«WMS остатки»](https://docs.google.com/spreadsheets/d/1bvZLSNb-CdWzuyBScL6C6x2fw--U1F8BD9PY4krElc4/edit?gid=1848900035) на первое число месяца: товар в `Товар` (P), остаток в `Остаток` (T), заголовки во второй строке. Текущий меняющийся остаток не подставлять вместо месячного среза. |
| M | **План заказов на дату, руб** | В новом сервисе: `План v2.0 / число дней в месяце × Дней с остатком`. В действующей таблице здесь используется годовой план J; **это меняется**. |
| N | **Выполнение плана на дату, %** | `Факт заказов, руб / План заказов на дату, руб`. Если план на дату равен нулю или неизвестен — не рассчитывать. |
| O | **План заказов, руб с правилом 15 дней** | **Не переносить:** правило обнуления плана при активности менее 15 дней отменено для нового плана. |
| P | **Факт заказов, руб** | Сумма положительных `funnel_daily.orders_sum` с первого числа месяца по дату отчёта, с тем же сопоставлением `nm_id → wild`, что и в G. |
| Q | **Факт заказов, %** | `Факт заказов, руб / План v2.0`. Сейчас это формула Google Sheets `P/K`; в новом сервисе считать самостоятельно. При нулевом или неизвестном плане — не рассчитывать. |
| R | **Недопродажи на сегодня** | `План v2.0 / число дней в месяце × число прошедших календарных дней − Факт заказов, руб`. Показывать только положительный результат; иначе пусто. В новом сервисе брать **выбранную дату отчёта**, а не `TODAY()` из Google Sheets. |
| S | **Линейный прогноз, руб** | `Факт заказов, руб / число прошедших календарных дней × число дней в месяце`. |
| T | **Линейны прогноз, %** | В новом сервисе: `Линейный прогноз, руб / План v2.0`. В действующей таблице знаменатель — годовой план J; **это меняется**. |
| U | **Факт заказов, % с правилом 15 дней** | **Не переносить:** правило 15 дней больше не применяется. |
| V | **Прогноз, % с правилом 15 дней** | **Не переносить:** правило 15 дней больше не применяется. |
| W | **updatet_at** | Время последнего успешного пересчёта по часовому поясу `Europe/Moscow`. В интерфейсе назвать «Обновлено». |
| X | **Документация** | Служебный текст Google Sheets, не показатель плана; в новый сервис не переносить. |

## Общие правила

- **Ноябрьский v2.0 уже зафиксирован** в БД. Для последующих месяцев остаток берётся из WMS как месячный снимок. Ноябрьский «свободный остаток» из UNIT и поле «Остаток» в WMS — разные исходные величины; у результата нужно хранить источник и время среза.
- При просмотре прошлой даты **факт пересчитывается по исправленным данным**, которые есть сейчас. Зафиксированные остаток, плановые штуки, цена и план v2.0 не меняются автоматически. Исправление самого месячного среза оформляется отдельно.
- Факт по менеджерам распределяется по **дням заказов**. Общий факт по `wild` и сумма факта по менеджерам должны совпадать; заказы без известного менеджера относятся к группе «Без менеджера».
- Отрицательный остаток считать нулём. Неизвестный остаток и неизвестную цену не подменять нулём. Если знаменатель процента равен нулю, процент не рассчитывать. День без статуса не считать подтверждённым днём наличия.
- Для менеджерского **процента выполнения** ещё нужно утвердить, как делить месячный план между менеджерами при передаче товара. Сам факт по дням распределять уже можно.
- Перед автоматической фиксацией следующих месяцев нужно определить точное время среза WMS и правило для повторяющихся строк одного `wild` с разными остатками. Текущий справочник плана содержит поля только за 2026 год; источник плана для 2027 года потребуется согласовать отдельно.
